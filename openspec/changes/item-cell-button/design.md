## Context

当前项目需要创建棋盘的核心交互元件 ItemCellButton，支持单击选中、三击收取、长按拖动合并三种交互模式。同时需要建立可复用的动画系统，避免每次创建 UI 按钮时重复编写动画逻辑。

## Goals / Non-Goals

**Goals:**
- 创建 `ButtonAnimation` 动画基类，支持 TweenTransitionType 和 TweenEaseType 曲线控制
- 创建两个派生动画类：按下缩放、弹起放大
- 创建 `ItemCellButton` 脚本，集成动画系统、三击检测、长按拖动、选中状态管理
- 动画组件即插即用，与 UI 逻辑解耦

**Non-Goals:**
- 不实现合成/收取的游戏逻辑（由外部系统处理）
- 不实现拖动合并的完整流程（只实现拖动检测和视觉反馈）
- 不添加音效（留占位符）
- 不创建 .tscn 场景文件（只创建脚本，后续手动绑定）

## Decisions

### 1. 动画系统架构

**决策**: 使用 RefCounted 基类 + 子类继承，而非 Node 组件

**理由**:
- 动画是纯逻辑控制（操作 Tween），不需要节点树
- RefCounted 更轻量，创建/销毁无开销
- 通过 `target` 属性引用 Control 节点，保持解耦

**备选方案**: 使用 Node 组件 → 过于重量级，需要添加到节点树

### 2. 三击检测实现

**决策**: 在 button_up 时判断连击计数，而非 button_down

**理由**:
- 三击的"第 3 次点击"应该在释放时确认
- 避免误触（用户可能按下后取消）

### 3. 长按拖动触发

**决策**: 使用 Timer (0.3s) 检测长按，而非移动距离阈值

**理由**:
- 时间阈值更直观，易于调整
- 适合手机触摸屏（手指可能轻微抖动）

**备选方案**: 移动距离阈值 → 容易误判，用户体验不稳定

### 4. 选中状态管理

**决策**: 选中状态由外部系统控制（通过 select()/deselect() 方法）

**理由**:
- 合成逻辑需要跨按钮协调（选中 A → 点击 B → 判断是否可合并）
- 按钮本身不应该决定何时选中/取消

## Risks / Trade-offs

- **[动画性能]** 多个 Tween 同时运行可能影响性能 → 使用短时长动画（0.1-0.2s） mitigates
- **[拖动与三击冲突]** 长按后释放可能误触发三击 → _is_dragging 标志位跳过后续逻辑
- **[定时器泄漏]** Timer 未完成时按钮销毁可能导致问题 → 使用 await + 检查 is_inside_tree()
